# 01: Treatment screen: new basis wording, no `not_for_stage`

**Rank:** standard for the wording; follows a scheduler API contract change (the `not_for_stage` reason is removed, no field changes).

**Model:** Sonnet

**What to build:** The scheduler no longer uses the line's Fouré stage to choose which fungicides a line is offered. Every suggestion starts from the full fungicide list; the stage is shown as evidence only. The Treatment screen must say so.

- **Basis line.** In `TreatmentDetailView.vue` (the `BASIS` map), by the suggestion's `basis` value:

  | `basis` | Text |
  |---|---|
  | `stage_confirmed` | A scan confirmed stage N this week (N is `line_stage.stage`) |
  | `all_healthy_images` | Only healthy images this week |
  | `no_confirmed_stage` | No stage confirmed this week |

  `line_stage` (`stage`, `tally`, `window`) is unchanged; `stage` is the most severe stage confirmed in the last 7 days. The tally is not shown.
- **`not_for_stage` is gone.** The scheduler never serves `reason: not_for_stage` any more. `reason` is still a free string. An Excluded unit is out only for `rotation`, `no_interval` or a failed check. Remove: the label in `client/src/helpers/checks.js`; the fallback in the stub's `reasonOf` (`stub/suggestions.js`), which now falls back to the failed check, or `rotation` for a non-selectable unit; and the assertion in `stub/suggestions.test.js` that a unit is excluded as `not_for_stage`.
- Update `client/src/stub-contract/treatment.screen.test.js`, and `stub/suggestions.js` (`BASIS_TEXT`) if it repeats the screen wording. Refresh the OpenAPI copy the stub tests read, if there is one, from the scheduler's new export.
- Leave `tasks/wayfinder/treatment-steps/prototype.html` (an old prototype).

**Blocked by:** The scheduler ticket "Eligibility reads the stage-free list" (in the AI_NeSy_Framework repo, `tasks/implementation/indicator-driven-eligibility/issues/02-stage-free-eligibility.md`) must be done first, so the stub matches the real contract.
